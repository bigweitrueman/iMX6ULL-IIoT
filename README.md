- # 基于 i.MX6ULL 的 IIoT 智能视觉与环境监测网关

  ## 项目简介

  本项目基于正点原子 i.MX6ULL (Cortex-A7) 开发板，从零搭建 Linux 运行环境，并开发了一款集 UI 交互、底层硬件反控、局域网通信与 V4L2 机器视觉于一体的智能中控终端。系统采用 LVGL 作为图形引擎，结合 POSIX 多线程技术，实现了环境数据的实时感知与监控画面的极速抓拍，完美模拟了工业物联网 (IIoT) 及智能家居玄关中控的核心应用场景。

  ## 技术栈与硬件平台

  - **硬件平台:** 正点原子 i.MX6ULL (528MHz CPU, 512M DDR3, 8G eMMC)
  - **外设清单:** ATK-4342 4.3 寸 RGB LCD (480x272) + 免驱 USB 摄像头 (UVC)
  - **系统环境:** U-Boot, Linux Kernel 4.1.15, 根文件系统 (NFS/eMMC)
  - **核心软件库:** `LVGL 8.x` (GUI 框架), `cJSON` (数据解析), `V4L2` (多媒体采集), `pthread` (多线程)

  ## 核心功能模块 (项目演进路线)

  ### V1.0：底层驱动适配与 GUI 引擎构建

  - 完成 U-Boot 裁剪与 Linux 内核移植，打通 TFTP+NFS 网络联调环境。
  - 独立排查并修改 Device Tree (`.dts`)，解决异构屏幕驱动适配问题。
  - 成功移植 LVGL 图形库，实现多页面交互 (TabView) 与电容触摸事件响应。

  ### V2.0：打通 Linux 虚拟文件系统 (软硬结合)

  - 秉承 Linux“一切皆文件”理念，通过标准文件 I/O (open/write) 读写 `sysfs` 节点。
  - 在 LVGL UI 层实现 `lv_switch` 控制板载 LED 灯状态。
  - 在 LVGL UI 层实现 `lv_slider` 对屏幕背光 (PWM) 进行 0-7 级的平滑亮度调节。

  ### V3.0：多线程网络通信与数据看板

  - 基于 TCP Socket 实现与局域网 Ubuntu 上位机（Python 模拟气象服务器）的双向通信。
  - 引入 POSIX 多线程 (`pthread`)，剥离阻塞型网络请求与 LVGL 刷新主循环，保障极佳的 UI 帧率。
  - 集成 `cJSON` 库解析云端温湿度数据，配合定制中文字库实现 Dashboard 动态图表 (Chart) 渲染。

  ### V4.0：V4L2 视觉采集与单帧抓拍渲染

  - 重新配置并编译内核，开启 `USB Video Class (UVC)` 驱动支持。
  - 利用 V4L2 框架与 `mmap` 内存映射，获取底层 YUYV 视频流。
  - 自研纯整型 `YUYV转RGB565` 高效色彩空间转换算法，突破平台算力瓶颈。
  - 结合 LVGL 画布 (`lv_canvas/lv_img`)，实现零延迟的瞬间抓拍与画中画 (PiP) 同步显示。

  ### **V4.5：MJPEG 局域网推流旁路** 

  针对"无法在 PC 端远程查看摄像头画面"的需求，独立开发了 `mjpeg_streamer` 推流服务进程。利用摄像头硬件原生输出的 **MJPEG 压缩格式**，完全绕开 YUYV 色彩转换的算力开销，通过 **HTTP `multipart/x-mixed-replace`** 协议持续推帧，PC 端浏览器或 VLC 直接打开 `http://<板子IP>:8081/` 即可实时查看画面，实现了"板端 HMI 显示"与"PC 端远程监控"的双路并行。

  ## 开发踩坑记录与解决方案 (Troubleshooting)

  开发过程中经历了多次底层调优与架构重构，核心难点及解决思路如下：

  ### 1. 异构屏幕适配：点亮初始的分屏与重影顽疾

  - **问题描述：** 挂载 4.3 寸 LCD 屏幕后，画面出现严重的分裂、错位及重影现象。
  - **排查过程：** 排除硬件排线问题后，锁定为底层 RGB 时序不匹配。
  - **解决方案：** 深入修改内核设备树 `imx6ull-alientek-emmc.dts`，精准计算并调整 LCD 节点下的 `clock-frequency`（像素时钟频率），将其从默认的 51.2MHz 降至适配该屏幕的 **9MHz**，重新编译 `dtbs` 后画面完美恢复正常。

  ### 2. 系统固化：断电后内核配置丢失 (USB 摄像头掉线)

  - **问题描述：** 开启 UVC 驱动编译的新内核通过 TFTP 加载运行正常，但断电重启后摄像头 `/dev/video1` 节点消失。
  - **排查过程：** 发现 TFTP 仅将 `zImage` 下载至内存，重启后 U-Boot 仍从 eMMC 引导了未包含 UVC 驱动的旧内核。
  - **解决方案：** 深入修改 U-Boot 源码，开启宏 `CONFIG_FAT_WRITE` 以支持 FAT 文件系统写入功能。在 U-Boot 中利用 `fatwrite` 命令将存放在内存中的新内核与设备树永久固化至 eMMC 的第 1 分区，并重置 `bootcmd` 环境变量，实现完全脱机运行。

  ### 3. V4L2 视觉采集：算力瓶颈与 UI 阻塞

  - **问题描述：** i.MX6ULL 平台无硬件色彩转换单元，直接在主循环中处理 30fps 的摄像头视频流会导致 LVGL 界面严重卡死。
  - **解决方案：** 1. **架构降级求稳**：舍弃高频视频流，改为“按键触发单帧抓拍”策略，仅在抓拍瞬间调度 CPU 算力。 2. **算法极致优化**：摒弃耗时的浮点运算，全部采用位移 (`>>`) 和纯整数算法处理 YUYV 到 RGB565 的转换，将单帧处理时间压缩至极低，确保了中控面板的流畅体验。
